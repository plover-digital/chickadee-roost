Open by design

Two public repositories keep the boundaries clear: Chickadee owns the host controller and image builders; Chickadee Roost owns this website and service onboarding. Self-host on your own Linux machine, with local storage and no Kubernetes or external database.

Our hosted deployment is separate from the public core. The prototype is intended for trusted workflows; hostile shared-tenant isolation is still being developed.

Use Chickadee with your agent

  1. Sign in with GitHub and install the Chickadee App for your repositories.
  2. Open Agent access and create a named token with read-only or management access, then choose Full account (all current and future repositories) or specific repositories.
  3. Put the token in your agent’s secret store as CHICKADEE_TOKEN, and give your agent the plain-text instructions at /llms.txt.

Tokens expire after 1, 7, 30 or 90 days (30 days by default) or when you revoke them. They keep working after browser sign-out and website restarts. GitHub can independently require reauthorization.

Give this to your agent

Read {{.PublicURL}}/llms.txt for the API contract.
Use CHICKADEE_TOKEN from the environment as a Bearer token.
Inspect my authorized repositories and applied service state.
Use only enabled runner labels. Ask before pausing or disconnecting a service.
Never print tokens or commit them to files.

The JSON API lives under /api/v1. It supports repository discovery, queue selection, enrollment and activation, pause, resume and disconnect requests. GitHub continues to match and run jobs; submit workflows through GitHub. Requests can await approval or capacity.

Full account management tokens can configure organization repository and workflow policy and request organization lifecycle changes when GitHub verifies the user as an organization owner. Specific-repository tokens retain access to personal services and queue settings for their existing legacy organization services. You can also manage organizations in the browser dashboard.
